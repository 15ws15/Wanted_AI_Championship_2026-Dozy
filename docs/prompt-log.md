# 프롬프트 개선 기록

이 서비스의 핵심은 "할 일을 5분 안에 할 수 있는 한 가지 행동으로 바꾸는 것"이다.
그 출력 품질은 프롬프트가 전부다. 아래는 실제로 측정하고 고친 기록이다.

측정 방법: 서로 다른 유형의 할 일 10종(문서 작업, 신체 활동, 가사, 학습, 행정, 감정적 연락)을
매 버전마다 동일하게 넣고 출력을 사람이 판정했다. 모델은 `gemini-3.5-flash-lite` 고정.

판정 기준(CLAUDE.md §5.1): **그 문장을 읽고 5초 안에 뭘 해야 할지 그림이 그려지는가.**

---

## v1 — 단일 프롬프트에 규칙 + 예시 + 질문을 모두 담음

예시를 `할 일: X → Y` 형식 목록으로 6개 넣고, 맨 아래에 사용자의 할 일을 붙였다.

측정 결과 (10종 중):

| 할 일 | 출력 | 문제 |
|---|---|---|
| 방 청소 | 메일함 열어서 가장 위 메일 하나만 읽기 | 예시 문장을 그대로 복사 |
| 영어 공부 | `할 일:` + 줄바꿈 + 스마트폰을 들어 캘린더 앱 열기 | 접두어 누출 |
| 연말정산 서류 준비 | `할 일:   غ → 화면을 켜고...` | 접두어 + 아랍 문자 + 화살표 누출 |
| 이력서 업데이트 | 모니터 전원 켜기 | 할 일과 무관한 일반적 답 |

**진단**: 예시의 형식(`할 일: X → Y`)과 출력 형식이 충돌한다. 모델이 *답하는* 대신
*예시 목록을 이어쓰고* 있었다. 접두어 누출은 그 증상이다.

## v2 — 규칙·예시를 `system_instruction`으로, 할 일을 `input`으로 분리

**고쳐진 것**: 접두어 누출과 쓰레기 문자가 사라졌다. 출력이 항상 한 줄이 됐다.

**남은 것**: 답이 여전히 다른 할 일의 것이었다. `영어 공부 → 세탁기 문 열고 젖은 옷 넣기`,
`병원 예약하기 → 세탁기 문 열고 빨랫감 넣기`.

## v3 — `max_output_tokens` 256 → 1024

v2를 조사하다 출력이 문장 중간에서 잘린 것을 발견했다:
`책상 위에 있는 책 한 권을 펼`, `서 작성" (Report writing`.

**진단**: thinking 토큰이 `max_output_tokens`를 같이 쓴다. 256으로는 추론이 예산을
다 먹고 답이 잘렸고, 마지막 줄만 취하는 후처리가 **추론 조각**을 답으로 반환하고 있었다.
v2에서 본 "남의 답"의 상당수가 사실 이것이었다.

**고쳐진 것**: 모든 출력이 완결된 문장이 됐다.

## v4 — 예시 목록을 제거하고 "조건"으로 서술 (현재 버전)

v3 이후에도 남은 교차 오답의 원인은 예시 목록 자체였다. 목록이 있는 한 모델은
그 안에서 답을 고르려 한다. `그대로 베끼지 말 것` 같은 부정 지시는 듣지 않았다.

예시 6줄을 통째로 지우고, 대신 관찰된 실패를 규칙으로 직접 적었다:

> 사용자가 방금 말한 바로 그 할 일에서 직접 이어진다. **다른 일에 어울리는 행동을 답하면 틀린 답이다.**

어미가 `~한다`/`~하기`로 섞이던 것도 규칙 한 줄로 통일했다.

**측정 결과: 10/10 해당 할 일에 맞는 실행 가능한 행동.**

| 할 일 | 출력 |
|---|---|
| 보고서 작성 | 한글 프로그램을 열기 |
| 운동하기 | 운동화 끈을 양쪽 다 묶기 |
| 방 청소 | 바닥에 있는 옷 한 벌 집어 들기 |
| 논문 읽기 | PDF 파일을 더블클릭해서 열기 |
| 영어 공부 | 단어장 앱을 연다 |
| 친구한테 미안하다고 연락하기 | 카카오톡 앱을 열기 |
| 연말정산 서류 준비 | 국세청 홈택스 홈페이지 접속하기 |
| 이력서 업데이트 | 이력서 파일 더블클릭해서 열기 |
| 코딩 테스트 준비 | 코딩 테스트 플랫폼 사이트를 브라우저에 띄우기 |
| 병원 예약하기 | 스마트폰에서 지도 앱을 연다 |

재귀 쪼개기(depth 0→3)도 함께 검증했다. 각 단계가 실제로 더 작아지고 앞 단계와 이어진다:

```
운동하기
  운동복 바지 입기
    침대에 앉아서 바지 한쪽 다리 밀어넣기
      침대에 앉아 양손으로 바지 허리띠 잡기
        엄지손가락으로 바지 고리 하나 걸기
```

## 측정 중에 발견한 함정

한동안 "라우트를 거치면 품질이 무너지는데 SDK를 직접 부르면 멀쩡한" 현상을 쫓았다.
원인은 코드가 아니라 **측정 도구**였다 — Git Bash의 `curl`이 한글 UTF-8 본문을 깨뜨려
모델에 깨진 제목이 전달되고 있었다. 이후 모든 측정은 UTF-8을 명시한 HTTP 요청으로 했다.

품질 문제를 프롬프트 탓으로 돌리기 전에 입력이 온전히 도착하는지부터 확인해야 한다.

## 남은 한계

- 어미가 약 30% 확률로 `~한다`로 나온다. 의미에는 영향이 없어 후처리하지 않았다.
  한국어 어미 변환은 규칙으로 안전하게 처리하기 어렵고, 잘못 바꾸면 문장이 망가진다.
- `병원 예약하기 → 지도 앱을 연다`가 10종 중 가장 약하다. 전화 앱이 맞다.
- 무료 티어는 분당 15회 제한이 있다. 초과 시 사용자에게 몇 초 뒤에 다시 누르라고 안내한다.

# 추천 기능 (Phase 2)

목록 전체를 맥락으로 주고 "지금 가장 시작하기 쉬운 하나"를 고르게 하는 기능이다.
쪼개기와 달리 **한 번에 통과했다.** v4에서 배운 것을 처음부터 적용했기 때문이다.

- 예시 목록을 주지 않았다. 고르는 기준만 우선순위 순으로 서술했다.
- 출력 형식을 프롬프트로 부탁하지 않고 **JSON 스키마로 강제**했다
  (`response_format: { mime_type: 'application/json', schema }`).
  CLAUDE.md는 코드펜스를 벗겨내라고 했지만, 스키마를 걸 수 있으면 벗겨낼 것 자체가 생기지 않는다.
  폴백은 그대로 남겼다 — 범위 밖 번호가 오면 첫 항목으로 되돌린다.

측정 결과:

| 목록 | 고른 것 | 이유 |
|---|---|---|
| 이사 준비 / 전기요금 내기 / 운동 시작하기 | 전기요금 내기 | 준비물 없이 바로 끝낼 수 있어요 |
| 발표자료 40장 만들기 / 팀원한테 회의록 공유하기 / 신년 계획 세우기 | 회의록 공유하기 | 준비물이 적고 단계가 짧아요 |
| 연말정산(마감 내일까지) / 대청소 / 우산 챙기기 | 우산 챙기기 | 준비물이 적고 가장 쉬워요 |

세 번째가 의도한 동작이다. 마감이 임박한 항목을 제치고 착수 비용이 가장 낮은 것을 골랐다.
CLAUDE.md §5.4의 기준 순서(착수 비용 > 장애물 해제 > 마감 임박)가 그대로 지켜졌다.
이 서비스는 마감 관리 도구가 아니라 착수 도구이므로 이 순서가 맞다.

말투는 한 번 고쳤다. 초기 출력이 `준비물이 적고 단계가 짧습니다`로 나와
앱 전체의 `~요` 체와 어긋났다. 규칙 한 줄을 더해 통일했다.

# v5 — "당연한 소리"라서 동기부여가 안 되는 문제

사용자 피드백: *"보고서 작성을 쪼갰는데 '빈 한글 파일 열기'는 너무 당연해서 동기부여가 안 된다."*

## 두 가지가 겹쳐 있었다

**1. v4가 스펙의 의도를 절반 잃었다.**
CLAUDE.md §5.1의 예시는 "빈 문서 열고 **제목만 쓰기**"다. 뒷부분이 핵심이다 — 하고 나면 화면에
무언가 남는다. 그런데 v4의 출력은 `한글 프로그램을 실행하고 새 빈 문서를 누르기`.
"구체적인 신체 동작이나 화면 조작"을 강조한 규칙이 모델을 물리적 준비 동작 쪽으로만 밀어붙였다.

**2. 막힘의 종류가 두 가지인데 하나로 취급했다.**

| | 막는 것 | 맞는 처방 |
|---|---|---|
| 운동, 청소, 설거지, 빨래 | 몸 | 준비 동작. "운동복으로 갈아입기"는 실제로 효과가 있다 |
| 보고서, 발표자료, 공부, 기획 | 막막함 | 흔적이 남는 행동. 파일을 열면 **미루게 만든 바로 그 빈 화면**을 마주할 뿐이다 |

후자에 전자의 처방을 내리고 있었다. 그래서 당연하게 느껴진 것이다.

## 고친 것

프롬프트가 먼저 어느 쪽인지 판단하게 하고, 막막함이 막는 일에는
"프로그램이나 파일을 여는 것은 답이 될 수 없다"를 명시적으로 금지했다.
v4의 교훈대로 예시 목록은 넣지 않았다. 기준만 서술했다.

## 도중에 두 번 되돌렸다

- `잘할 필요는 없다. 엉망이어도 되는 분량으로 잡는다` → 출력에
  `첫 문장에 쓰레기 단어 '제목'만 적기`가 나왔다. 프롬프트의 부정적 어휘가 그대로 샜다.
  `완성도를 신경 쓰지 않아도 되는 분량으로 잡는다`로 바꾸자 사라졌다.
- 그다음 글쓰기 일이 전부 `제목 한 줄 적기`로 수렴했다. 제목이 가장 뻔한 답이기 때문이다.
  `늘 제목일 필요는 없다. 그 일에서 가장 먼저 정해져야 하는 것으로 고른다`와
  `하나만 고르기 어려우면 후보를 여러 개 늘어놓게 해도 좋다`를 더해 풀었다.

## 측정 결과 (10/10)

| 할 일 | v4 (전) | v5 (후) |
|---|---|---|
| 보고서 작성 | 한글 프로그램을 실행하고 새 빈 문서를 누르기 | 이번 주 목표 매출액 한 문장 적기 |
| 발표자료 만들기 | — | 첫 페이지 제목에 들어갈 단어 세 개 적어보기 |
| 기획안 쓰기 | — | 기획서에 들어갈 목차 항목 3개 적기 |
| 영어 공부 | 단어장 앱을 연다 | 오늘 공부할 교재에서 모르는 단어 3개만 찾아 적기 |
| 이력서 업데이트 | 이력서 파일 더블클릭해서 열기 | 최근에 끝낸 프로젝트 이름 하나 적기 |
| 코딩 테스트 준비 | 코딩 테스트 플랫폼 사이트를 브라우저에 띄우기 | 풀 문제 번호 하나 고르기 |
| 설거지 | — | 고무장갑을 끼고 수세미에 세제를 짜기 |
| 방 청소 | 바닥에 있는 옷 한 벌 집어 들기 | 바닥에 있는 물건 하나 집어서 쓰레기통에 넣기 |
| 운동하기 | 운동화 끈을 양쪽 다 묶기 | 운동복 바지만 먼저 입기 |

몸 쓰는 일은 v4와 같은 성격의 답이 나온다. 바뀐 것은 머리 쓰는 일뿐이고, 그게 의도다.

`이것도 어려워요`는 그대로 물리적 준비 동작까지 내려간다. 이제 사다리가 제대로 선다 —
**첫 칸은 뭔가를 만들어내고, 그것조차 어려우면 그때 파일을 여는 단계로 내려간다.**

## 타임아웃을 10초 → 25초로 올렸다

측정 중 절반이 타임아웃으로 끊겼다. 원인을 프롬프트 길이로 의심했으나 아니었다:
**13토큰짜리 프롬프트도 11.8초가 걸렸다.** 449토큰인 우리 프롬프트는 9.2초였다.
느린 것은 우리가 아니라 무료 티어 자체다. 실측 분포는 2.1초 ~ 21.4초.

CLAUDE.md §6.2는 10초를 규정하지만, 그 값이면 정상 응답의 절반을 헛되이 버린다.
Vercel Hobby 함수 한도는 300초라 배포 쪽 제약이 아니어서 25초로 올렸다.
