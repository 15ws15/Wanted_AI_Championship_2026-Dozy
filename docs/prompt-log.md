# 프롬프트 개선 기록

이 서비스의 핵심은 "할 일을 5분 안에 할 수 있는 한 가지 행동으로 바꾸는 것"이다.
그 출력 품질은 프롬프트가 전부다. 아래는 실제로 측정하고 고친 기록이다.

측정 방법: 서로 다른 유형의 할 일 10종(문서 작업, 신체 활동, 가사, 학습, 행정, 감정적 연락)을
매 버전마다 동일하게 넣고 출력을 사람이 판정했다. 모델은 `gemini-3.5-flash-lite` 고정.

판정 기준(CLAUDE.md §5.1): **그 문장을 읽고 5초 안에 뭘 해야 할지 그림이 그려지는가.**

---

## v1 — 단일 프롬프트에 규칙 + 예시 + 질문을 모두 담음

예시를 `할 일: X → Y` 형식 목록으로 6개 넣고, 맨 아래에 사용자의 할 일을 붙였다.

측정 결과 (10종 중):

| 할 일 | 출력 | 문제 |
|---|---|---|
| 방 청소 | 메일함 열어서 가장 위 메일 하나만 읽기 | 예시 문장을 그대로 복사 |
| 영어 공부 | `할 일:` + 줄바꿈 + 스마트폰을 들어 캘린더 앱 열기 | 접두어 누출 |
| 연말정산 서류 준비 | `할 일:   غ → 화면을 켜고...` | 접두어 + 아랍 문자 + 화살표 누출 |
| 이력서 업데이트 | 모니터 전원 켜기 | 할 일과 무관한 일반적 답 |

**진단**: 예시의 형식(`할 일: X → Y`)과 출력 형식이 충돌한다. 모델이 *답하는* 대신
*예시 목록을 이어쓰고* 있었다. 접두어 누출은 그 증상이다.

## v2 — 규칙·예시를 `system_instruction`으로, 할 일을 `input`으로 분리

**고쳐진 것**: 접두어 누출과 쓰레기 문자가 사라졌다. 출력이 항상 한 줄이 됐다.

**남은 것**: 답이 여전히 다른 할 일의 것이었다. `영어 공부 → 세탁기 문 열고 젖은 옷 넣기`,
`병원 예약하기 → 세탁기 문 열고 빨랫감 넣기`.

## v3 — `max_output_tokens` 256 → 1024

v2를 조사하다 출력이 문장 중간에서 잘린 것을 발견했다:
`책상 위에 있는 책 한 권을 펼`, `서 작성" (Report writing`.

**진단**: thinking 토큰이 `max_output_tokens`를 같이 쓴다. 256으로는 추론이 예산을
다 먹고 답이 잘렸고, 마지막 줄만 취하는 후처리가 **추론 조각**을 답으로 반환하고 있었다.
v2에서 본 "남의 답"의 상당수가 사실 이것이었다.

**고쳐진 것**: 모든 출력이 완결된 문장이 됐다.

## v4 — 예시 목록을 제거하고 "조건"으로 서술 (현재 버전)

v3 이후에도 남은 교차 오답의 원인은 예시 목록 자체였다. 목록이 있는 한 모델은
그 안에서 답을 고르려 한다. `그대로 베끼지 말 것` 같은 부정 지시는 듣지 않았다.

예시 6줄을 통째로 지우고, 대신 관찰된 실패를 규칙으로 직접 적었다:

> 사용자가 방금 말한 바로 그 할 일에서 직접 이어진다. **다른 일에 어울리는 행동을 답하면 틀린 답이다.**

어미가 `~한다`/`~하기`로 섞이던 것도 규칙 한 줄로 통일했다.

**측정 결과: 10/10 해당 할 일에 맞는 실행 가능한 행동.**

| 할 일 | 출력 |
|---|---|
| 보고서 작성 | 한글 프로그램을 열기 |
| 운동하기 | 운동화 끈을 양쪽 다 묶기 |
| 방 청소 | 바닥에 있는 옷 한 벌 집어 들기 |
| 논문 읽기 | PDF 파일을 더블클릭해서 열기 |
| 영어 공부 | 단어장 앱을 연다 |
| 친구한테 미안하다고 연락하기 | 카카오톡 앱을 열기 |
| 연말정산 서류 준비 | 국세청 홈택스 홈페이지 접속하기 |
| 이력서 업데이트 | 이력서 파일 더블클릭해서 열기 |
| 코딩 테스트 준비 | 코딩 테스트 플랫폼 사이트를 브라우저에 띄우기 |
| 병원 예약하기 | 스마트폰에서 지도 앱을 연다 |

재귀 쪼개기(depth 0→3)도 함께 검증했다. 각 단계가 실제로 더 작아지고 앞 단계와 이어진다:

```
운동하기
  운동복 바지 입기
    침대에 앉아서 바지 한쪽 다리 밀어넣기
      침대에 앉아 양손으로 바지 허리띠 잡기
        엄지손가락으로 바지 고리 하나 걸기
```

## 측정 중에 발견한 함정

한동안 "라우트를 거치면 품질이 무너지는데 SDK를 직접 부르면 멀쩡한" 현상을 쫓았다.
원인은 코드가 아니라 **측정 도구**였다 — Git Bash의 `curl`이 한글 UTF-8 본문을 깨뜨려
모델에 깨진 제목이 전달되고 있었다. 이후 모든 측정은 UTF-8을 명시한 HTTP 요청으로 했다.

품질 문제를 프롬프트 탓으로 돌리기 전에 입력이 온전히 도착하는지부터 확인해야 한다.

## 남은 한계

- 어미가 약 30% 확률로 `~한다`로 나온다. 의미에는 영향이 없어 후처리하지 않았다.
  한국어 어미 변환은 규칙으로 안전하게 처리하기 어렵고, 잘못 바꾸면 문장이 망가진다.
- `병원 예약하기 → 지도 앱을 연다`가 10종 중 가장 약하다. 전화 앱이 맞다.
- 무료 티어는 분당 15회 제한이 있다. 초과 시 사용자에게 몇 초 뒤에 다시 누르라고 안내한다.
